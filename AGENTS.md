## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

When the user types `/graphify`, use the installed graphify skill or instructions before doing anything else.

Rules:
- When graphify-out/graph.json exists, run `graphify query "<question>"` before your first grep, search or source-file read for a codebase question, and put this rule in every subagent prompt that explores code. Read raw files only for lines the graph or an earlier read already located. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- Dirty graphify-out/ files are expected after hooks or incremental updates; dirty graph files are not a reason to skip graphify. Only skip graphify if the task is about stale or incorrect graph output, or the user explicitly says not to use it.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).
- A committed graphify-out/graph.json is rewritten whole on every build, so a large diff to it in a pull request is expected. Do not flag it as churn or suggest skipping the graph rebuild or its hooks.

## quickshell config

Pure QML Wayland shell for niri. No build, no tests, no lint.
- Entry: `shell.qml` — `Variants { model: Quickshell.screens }` per overlay. Add new overlays there.
- `services/*.qml` = `pragma Singleton` global state, accessed by filename. `modules/*.qml` = windows/widgets. `style/Theme.qml` = M3 Expressive tokens.
- Run/verify: `quickshell` (run); config hot-reloads on save (`qs log` to watch the running instance — its stderr goes to /dev/null under niri). Exercise state live: `qs ipc call <settings|launcher|clipboard|center|wallpaper|bar> toggle` (see `services/ShellState.qml:90-178`).
- No `qmlformat`/`qmllint` in repo — verification is reload + stderr, not a check command.

## conventions

- Singleton files: `pragma Singleton` + `Singleton {}` root (never `QtObject`/`Item`). Add `pragma ComponentBehavior: Bound` when file defines `component` blocks or nested handlers access outer `id`s.
- Type all functions: `function foo(x: string): void`. Use `?.` / `??` on nullable Quickshell models. `Process.command` must be a string array.
- Persist across config hot-reloads with `PersistentProperties { reloadableId: "..." }` (not `reloadSource`). Hold Pipewire nodes with `PwObjectTracker`.
- Colors: use `Theme.*` roles only, never hardcode hex. `style/Colors.json` is generated by matugen (`SchemeExpressive`) and watched live via `FileView` — don't hand-edit; `Theme.normalizeHex` already handles `RRGGBBAA`. The user's wallpaper command `awww img <file>` is routed through matugen by a `/usr/local/bin/awww` shim, so the palette follows the wallpaper; the matugen config calls the real `/usr/sbin/awww` to avoid looping through that shim. `FileView.watchChanges` only emits `fileChanged` — the live recolor relies on the explicit `onFileChanged: colorsFile.reload()` in `style/Theme.qml`.
- Niri state lives in `services/Niri.qml` (`niri msg -j event-stream` via `SplitParser` + one-shot `workspaces`/`windows`/`keyboard-layouts` queries). Call `Niri.focusWorkspace()`, `Niri.focusedWindow`, `Niri.workspacesFor(output)` from modules — don't spawn `niri msg` elsewhere.
- Overlays key visibility by screen-name string in `services/ShellState.qml` (`""` = closed). Niri keybinds call `toggleOn(output)`; scripts/tests call bare `toggle()` (first screen). Match the existing overlay pattern: `ExclusionMode.Ignore`, `WlrLayer.Overlay`, `WlrKeyboardFocus.Exclusive` only when shown, `visible: shown || opacity > 0.001` so fade-out plays, Esc + click-outside to dismiss.
- Setting the wallpaper from inside the shell is `Quickshell.execDetached(["awww", "img", path])` — the same shim→matugen path as the terminal. `modules/WallpaperDropArea.qml` is the shared drag-and-drop handler, used by the desktop surface (`WallpaperDrop`, Background layer, per screen) and the bar band.
- Name collision guard: `services/SystemMonitor.qml` is deliberately *not* `SystemStats` so `import "../services"` doesn't shadow `modules/SystemStats.qml`.
- Local config: `Weather.lat/lon` hardcoded to Moscow (`services/Weather.qml:15-16`) — change per city. `launcher-usage.json` (counts/favorites) and `.qmlls.ini` (volatile `/run/... buildDir`) are gitignored runtime state — don't edit or commit.
