## quickshell config

Pure QML Wayland shell for niri. No build; `scripts/check-qml.py` is the static guardrail.
- Entry: `shell.qml` — `Variants { model: Quickshell.screens }` per overlay. Add new overlays there.
- `services/*.qml` = `pragma Singleton` global state, accessed by filename. `modules/*.qml` = windows/widgets. `style/Theme.qml` = M3 Expressive tokens.
- Run/verify: `quickshell` (run); config hot-reloads on save (`qs log` to watch the running instance — its stderr goes to /dev/null under niri). Exercise state live: `qs ipc call <settings|launcher|clipboard|center|tray|weather|clock|system|wallpaper|bar> toggle` (IpcHandlers in `services/ShellState.qml`: `theme dark|light`, `style m3|blur|new|nothing|newNothing|old|custom`, `colorscheme matugen|oled|gruvbox`, `font material|mono|old`, `blur wallpaper|window`; `notifs` in `services/Notifications.qml`).
- No `qmlformat`/`qmllint` in repo — verification is reload + stderr, not a check command. `./install.sh --check` is the doctor; `bash -n install.sh` checks the installer without running it; `python3 scripts/check-qml.py` checks the conventions above (singleton roots, FileView flags, hex colors, i18n keys) and runs in CI. If `qmllint` is available, `/usr/lib/qt6/bin/qmllint -I . -I /usr/lib/qt6/qml -i services/qmldir -i modules/qmldir -i style/qmldir shell.qml modules/*.qml services/*.qml style/*.qml` catches most QML errors (Qt6's binary lives outside `$PATH`; `-v` prints the version, not verbose output; `.qmllint.ini` sets `MaxWarnings=0`, so any new warning fails CI).
- Public docs: `README.md` (English), `README.ru.md` (Russian), `CONTRIBUTING.md`, `LICENSE`. Screenshots live in `assets/screenshots/` and are redacted; `assets/social-preview.png` is the GitHub preview. `final-dark.png` stays in the repo but is deliberately not used by the docs (it exposes a home path and an editor UI). The old `readme.md` is gone — edit the two READMEs together.
- Installer: `./install.sh` installs packages/fonts, writes matugen configs with absolute paths to this checkout, installs the `/usr/local/bin/awww` shim, creates dirs, and safely appends niri/ghostty/qt6ct pointers with `.bak.*` backups. It never edits keybinds — it prints them. Flags: `--check`, `--no-apply`, `--no-packages`, `--no-fonts`, `--no-shim`, `--link`.
- Vendor files: `install/awww` is the shim source (installed root-owned to `/usr/local/bin/awww`, don't edit the installed copy), `install/matugen/{config,light}.toml` + `templates/quickshell.json`.

## conventions

- Singleton files: `pragma Singleton` + `Singleton {}` root (never `QtObject`/`Item`). Add `pragma ComponentBehavior: Bound` when file defines `component` blocks or nested handlers access outer `id`s.
- Type all functions: `function foo(x: string): void`. Use `?.` / `??` on nullable Quickshell models. `Process.command` must be a string array.
- Every `FileView` carries `preload: false` + `blockAllReads: true` (and `blockWrites: true` when it has a `JsonAdapter`/`writeAdapter()`), placed **after** `path:` — the wrapper reads them while `path` is assigned, so above it they do nothing and the async reader thread costs ~3 MB each (`services/SystemMonitor.qml` alone was 20 MB). Reads are then synchronous; a `FileView` that had no other caller needs `Component.onCompleted: text()`.
- Persist across config hot-reloads with `PersistentProperties { reloadableId: "..." }` (not `reloadSource`); it does not survive a process restart, so state that must outlive a reboot goes to a `FileView` + `JsonAdapter` JSON (`services/ShellState.qml` → `shell-state.json`). Hold Pipewire nodes with `PwObjectTracker`.
- Colors: use `Theme.*` roles only, never hardcode hex. Two matugen palettes are watched live via `FileView`: `style/Colors.json` (dark, written by the wallpaper pass in `$XDG_CONFIG_HOME/matugen/config.toml`, default `~/.config/matugen/config.toml`) and `style/ColorsLight.json` (light, written by a second `matugen -m light image … -c $XDG_CONFIG_HOME/matugen/light.toml` pass that the shell runs itself — matugen takes the mode from the command line only, one run cannot emit both). Both are generated, don't hand-edit; `Theme.normalizeHex` handles `RRGGBBAA`, and a missing light file falls back to `Theme.baselineLightScheme` in the same mode. `ShellState.themeMode` picks the file; `styleMode` and `colorScheme` layer their packs on top and each has a light twin. The light pass is guarded by `[ light -nt dark ]` and skips re-applying the wallpaper because `light.toml` has no `[config.wallpaper]` — keep its source-color settings in sync with `config.toml`. It locates both palettes with `Quickshell.shellPath(...)` (not `$HOME`) and quotes paths with `Theme.shQuote`, so the checkout may live outside `~/.config/quickshell`; `Theme.configHome` follows `XDG_CONFIG_HOME`. The user's wallpaper command `awww img <file>` is routed through matugen by the `/usr/local/bin/awww` shim (root-owned: don't edit; source is `install/awww`); the matugen config calls the real `/usr/bin/awww` to avoid looping. `FileView.watchChanges` only emits `fileChanged` — the live recolor relies on the explicit `onFileChanged: ….reload()`.
- The shell also mirrors its palette onto the rest of the desktop from `services/SystemTheme.qml` (called once from `shell.qml`): GTK3/GTK4 `gtk.css`, the ghostty theme `$XDG_CONFIG_HOME/ghostty/themes/Quickshell` (needs `theme = Quickshell` in ghostty's config; reloaded with `pkill -USR2 -x ghostty`), `$XDG_CONFIG_HOME/qt6ct/colors/matugen.conf` (needs `color_scheme_path` pointing at it), `$XDG_CONFIG_HOME/niri/quickshell.kdl` — generated whole: the niri border/focus-ring colors, the `layer-rule` that carries the blur source and the `animations` switch (needs `include "quickshell.kdl"` in niri's `config.kdl`, placed after `layout.kdl` — niri merges includes positionally; gradients are written whole, angles included, because niri replaces a gradient node on include merge instead of merging its properties) — and `gsettings … color-scheme`. All paths go through `SystemTheme.configHome`, which follows `XDG_CONFIG_HOME` and falls back to `~/.config`; the legacy `~/.config` hardcoding is gone. A file is written only when its content changed; generated files may be hand-edited but are regenerated on the next theme change. The «Приложения» settings tab (one row, four chips — GTK, Qt, Ghostty, Niri) gates each target: its ids are stored as the disabled list in `ShellState.themeAppsOff` (empty/absent = all on), `SystemTheme.gtkOn/qtOn/ghosttyOn/niriOn` read it, a disabled target is never written and keeps its last colors, and `onThemeAppsOffChanged` re-runs `SystemTheme.applyAll()` so switching one back on applies the current palette immediately (`qs ipc call settings app ghostty false`).
- The blur source («Блюр» in the settings menu, hidden under M3 Inspired, Nothing and Old because nothing blurs there) is niri policy: «Обои» — the wallpaper alone, the default — writes nothing into the rule, because niri already x-ray-blurs whatever blur a client requests and leaves effect-less surfaces alone (an explicit `xray true` also paints the wallpaper behind the full-screen transparent popups, hiding the windows under them); «Окна» writes `xray false` so what actually sits under the plate, windows included, blurs. It lives in that same `quickshell.kdl` `layer-rule` and is read back from the file at shell start (`SystemTheme.sync`) — no `xray` line means «Обои», which is why the generated niri config, not `shell-state.json`, is the record for it. `ShellState.blurSource` is the live copy; `niriArmed` keeps the first evaluation of the generated text from overwriting the file before the read.
- Motion is two settings, not one. `ShellState.animationMode` («Анимации» in the settings menu — «Выключены» / «Обычные» / «Медленные», `qs ipc call settings animations off`) drives only the shell: `style/Theme.qml` turns it into `Theme.motion` (0 / 1 / 1.6), every `dur*` token is `root.old ? 0 : root.dur(ms)`, and `Theme.dur(ms)` scales the few hardcoded micro-durations (Workspaces, WindowTitle, LayoutBadge, Bar, Pet). Ambient's seasonal dressing is decoration and keeps its own motion; the WindowTitle marquee never starts while motion is 0, because its infinite zero-duration loop would churn (`scrolling` gates it).
- `ShellState.niriAnimation` («Анимации niri», `qs ipc call settings nirianimations off`) is the compositor's own level and goes into the same generated `quickshell.kdl`: «Выключены» writes `animations { off }`, «Медленные» — `slowdown 1.0`, «Обычные» writes nothing so the user's own `animations.kdl` (included earlier, merged per property) stands. The file is regenerated whole, so «Обычные» simply drops the block — no read-back like the blur source, `shell-state.json` is the record. Like the colors, that write sits behind the `niriOn` gate.
- Window rounding («Скругление окон») is the third niri write into that same `quickshell.kdl`: a catch-all `window-rule { geometry-corner-radius N; clip-to-geometry true }` (`ShellState.windowRadius`, 0–24) that wins because the file is included last and niri applies matching window rules in order. `-1` (the untouched slider, and the value of a missing key) writes nothing, so the user's own `window-rules.kdl` keeps its radius. The adapter holds it as a string because an absent key must read as unset while an int would default to 0 (square corners); `shell-state.json` is the record — no read-back, like `niriAnimation`. The row is always visible but its write sits behind `niriOn`. Its slider is the shared `modules/QsSlider.qml`, extracted from `QuickSettings.qml` (registered in `modules/qmldir`).
- Custom style pack: `ShellState.custom*` reads one sparse JSON string from `shell-state.json` (`custom`), so missing keys fall back to the defaults in `ShellState` and `Theme`. `Theme.customPalette` merges the sparse `palette` over `customDefaults` (baseline scheme + New graphite made opaque), and `Theme.scheme` returns it directly (acrylic alpha only on `surface_container`/`surface_container_high` when the acrylic knob is on). One palette serves both modes: `Theme.light` is `isLightColor(customPalette.surface)`, which drives only the terminal/desktop derivations. The corner ladder scales from `customRadius` (16 reproduces the M3 4/8/12/16/20/28/32/48 values; 0 squares it), `customBarRadius`/`customChipRadius` override the island/chip pills, and the border knob gates the hairline/rim/specular; `Theme.bevel` adds old-style bevels in `modules/GlassEdge.qml`. The settings **Custom** tab (`modules/Settings.qml`, 5th tab) owns the knobs and the 47-role palette; the HSV picker (`modules/ColorPicker.qml`, `modules/color.js`, tested by `tests/color.test.js`) commits only on «Готово», and sliders (`modules/IntSlider.qml`) write on release, because every palette write also reruns `SystemTheme`. Reset buttons clear one role, the palette overrides, or the whole pack. While Custom is active the `Тема` and `Цвета` rows are hidden.
- Niri state lives in `services/Niri.qml` (`niri msg -j event-stream` via `SplitParser` + one-shot `workspaces`/`windows`/`keyboard-layouts` queries). Call `Niri.focusWorkspace()`, `Niri.focusedWindow`, `Niri.workspacesFor(output)` from modules — don't spawn `niri msg` elsewhere.
- Overlays key visibility by screen-name string in `services/ShellState.qml` (`""` = closed). Niri keybinds call `toggleOn(output)`; scripts/tests call bare `toggle()` (first screen). Match the existing overlay pattern: `ExclusionMode.Ignore`, `WlrLayer.Overlay`, `WlrKeyboardFocus.Exclusive` only when shown, `visible: shown || opacity > 0.001` so fade-out plays, Esc + click-outside to dismiss.
- Countdown/stopwatch state lives in `services/ClockTools.qml`, not in `ClockPopup`: `LazyOverlay` destroys the window. `shell.qml` touches the singleton at startup so a running timer survives a reload while the popup is closed; the finish alarm is `notify-send` plus the freedesktop alarm sound because the popup may be shut.
- Lock screen: `modules/LockScreen.qml` owns one `WlSessionLock` (`reloadableId "quickshell-lock"`, so a QML reload keeps the session locked) plus two `IdleMonitor`s — 300 s → `lock()`, 450 s → `Niri.powerOffMonitors()` — and the `lock` IPC target (`qs ipc call lock lock`). Before suspend it holds a `systemd-inhibit --mode=delay` and watches logind `PrepareForSleep` through `dbus-monitor --system`: `true` → lock, release 150 ms later; `false` → re-arm. There is deliberately no IPC to unlock: only PAM ends it. Surfaces (`modules/LockSurface.qml`, one per monitor) share `services/LockAuth.qml`, a `PamContext` on the system `login` stack; the wallpaper comes from `awww query`, the card uses `Theme.popupSurface` and shows `Niri.currentLayout`. If the process dies while locked the compositor keeps the session locked, so test with a TTY at hand.
- Pet chat (`services/PetChat.qml`) is a bounded tool loop: one NVIDIA NIM call per round, `parallel_tool_calls: false`, three tool rounds, then one last call with `tool_choice: "none"` so it always answers in words. NIM takes the key from `NVIDIA_API_KEY` (`ShellState.nvidiaKey`) and answers in `content` only because the request sends `chat_template_kwargs: {"enable_thinking": false}` — Nemotron spends `max_tokens` on its thinking trace otherwise. Diagnostics are a fixed argv map — never `sh -c` with model input — and `ls` is restricted to non-hidden paths under `$HOME`; output is capped at 4 KB with a 3 s timeout and returned as untrusted `role: tool` content. `shell_action` calls `ShellState`/`Audio` directly, only reversible things, and opens overlays on `ShellState.petScreen`. History is in memory only; the window is lazy, so the singleton dies on a config reload.
- Setting the wallpaper from inside the shell is `Quickshell.execDetached(["awww", "img", path])` — the same shim→matugen path as the terminal. `modules/WallpaperDropArea.qml` is the shared drag-and-drop handler, used by the desktop surface (`WallpaperDrop`, Background layer, per screen) and the bar band.
- Name collision guard: `services/SystemMonitor.qml` is deliberately *not* `SystemStats` so `import "../services"` doesn't shadow `modules/SystemStats.qml`.
- Clipboard pins (`services/ClipboardPins.qml`) are decoded snapshots in `Quickshell.dataPath("clipboard")` plus a `pins.json` index, because `cliphist wipe` clears the history wholesale; the launcher maps them to `{…, pinned: true}` and hides the matching history row. Notification history and the muted-app list persist in the gitignored `notifications.json` through a `FileView` + `JsonAdapter`; restored rows have `live: null` and are marked seen. The tray popup renders `QsMenuOpener` entries manually — `QsMenuAnchor` cannot attach a platform menu to a layer-shell surface.
- Local config: `Weather.lat/lon` hardcoded to Moscow (`services/Weather.qml:15-16`) — change per city. The terminal for `Terminal=true` desktop entries is `$TERMINAL` (split on spaces), then `alacritty` (`modules/Launcher.qml`). `launcher-usage.json` (counts/favorites), `notifications.json`, `wallpaper-favorites.json`, `shell-state.json` (settings menu) and `.qmlls.ini` (volatile `/run/... buildDir`) are gitignored runtime state — don't edit or commit. `style/Colors*.json` are tracked fallbacks despite being generated.
