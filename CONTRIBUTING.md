# Contributing

This is a Quickshell configuration, not a compiled application: there is no
build step and no test suite. The shell reads QML at runtime and reloads itself
when a file changes.

## Run it

```sh
./install.sh --check   # verify the environment first
quickshell             # run in the foreground and watch stderr
qs log                 # logs of the running instance
```

Keep a terminal with `quickshell` or `qs log` open while editing. A QML error
shows up there and the previous configuration stays on screen.

## Check before sending a change

```sh
bash -n install.sh
qmllint -v -I . -I /usr/lib/qt6/qml shell.qml modules/*.qml services/*.qml style/*.qml
```

`qmllint` is part of Qt 6. On Arch it comes with `qt6-declarative`. The exact
QML import directory can be printed with `qtpaths6 --query QT_INSTALL_QML`.

If you changed QML, also run:

```sh
graphify update .
```

This repository keeps the knowledge graph in `graphify-out/`; the large diff is
expected.

## Rules of thumb

- Use `Theme.*` color roles, never hardcoded hex values.
- Keep services as `pragma Singleton` files with a `Singleton {}` root.
- Type function signatures and use `?.` / `??` on nullable Quickshell models.
- Persist reload-only state with `PersistentProperties`; state that must outlive
  the process (the settings menu) goes to a `FileView` + `JsonAdapter` JSON.
- Do not commit `launcher-usage.json`, `wallpaper-favorites.json`,
  `shell-state.json` or `.qmlls.ini`; they are local runtime state.
- `style/Colors.json` and `style/ColorsLight.json` are generated by matugen and
  tracked as a fallback. Commit them only when you intentionally update the
  fallback palette.
